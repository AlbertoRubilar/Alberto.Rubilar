Automatización de un proceso de generación de solicitudes de carga mediante Microsoft Forms, Power Automate, Power BI y Excel.

01 / OVERVIEW

De un proceso manual a una solicitud automatizada.

El proyecto nació a partir de la necesidad de simplificar la generación de templates utilizados para realizar cargas de información de tiendas dentro de una plataforma operacional.

El proceso original requería buscar manualmente cada tienda asociada a un bloque, identificar su Response ID y recopilar información adicional desde diferentes archivos.

Posteriormente, toda esta información debía consolidarse manualmente en un template Excel antes de poder realizar la carga.

La solución desarrollada automatiza gran parte de este proceso, dejando la intervención humana principalmente en la ejecución final de la carga.

02 / CHALLENGE

El proceso anterior.

Antes de la automatización, cada solicitud requería realizar manualmente múltiples búsquedas y cruces de información.

Primero era necesario identificar todas las tiendas pertenecientes a un mismo bloque mediante su código correspondiente.

Luego se debía localizar el Response ID de cada tienda y obtener información adicional relacionada con el estado de respuesta, nombre, estado de carga y fechas.

Finalmente, toda esta información se agrupaba manualmente dentro de un template preparado para realizar la carga en el sistema.

05 / AUTOMATION

Orquestación mediante Power Automate.

Power Automate actúa como el componente central de la solución, coordinando la captura, consulta, transformación y distribución de la información.

El flujo comienza con el trigger When a new response is submitted asociado al Microsoft Form.

Posteriormente se obtienen las respuestas del formulario y se utilizan Composes y variables para estructurar los parámetros utilizados durante el proceso.

El flujo realiza consultas sobre el dataset de Power BI y posteriormente procesa los registros obtenidos mediante Filter Array y Apply to Each.

También se realizan cruces con información almacenada en archivos de apoyo para completar los datos requeridos por el template.

06 / DATA SOURCES

Integración de información.

El código del bloque funciona como parámetro principal para identificar todas las tiendas asociadas a la solicitud.

A partir de este identificador se consulta el modelo semántico de Smart Censo Comunas, obteniendo los registros correspondientes.

Entre los datos utilizados se encuentran Response ID, Response Status, Response Name, estado de carga, código de auditor y fechas de inicio y término.

Esta información posteriormente se cruza con otras fuentes almacenadas en archivos para completar todos los campos requeridos.

08 / IMPACT

Impacto.

Menos trabajo manual

Se eliminan aproximadamente 15 minutos de trabajo manual por cada solicitud.

Ahorro operacional

El proceso permite recuperar aproximadamente dos horas de trabajo al día.

Menor intervención humana

La recopilación, cruce y preparación de la información dejan de depender de búsquedas manuales.

Proceso estandarizado

Cada solicitud sigue una estructura uniforme y genera un archivo preparado para la ejecución de la carga.
